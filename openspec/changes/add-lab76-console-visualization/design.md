# Design

## Context

См. `proposal.md`. Старый `OptimizeObserved` уже синхронно выдаёт веса. Компонент и UnitTest не вызывают libc. Нативный скрипт Apple Clang работает на macOS arm64; полного Xcode на машине нет.

## Goals / Non-Goals

**Goals:** показ реальных первых шагов задач с 1, 2, 5 и 10 весами, нулевой эффект на ABI и базовый тест, отказ при неверной демонстрации.

**Non-Goals:** GUI, новые события/методы, второй оптимизатор, изменение существующих замеров производительности.

## Decisions

1. Отдельный C89-клиент регистрирует прежнюю фабрику, получает `IEcoArtificialIntelligence` и `IEcoOptimizationTrace`, создаёт векторы и запускает `OptimizeObserved`. Фиксированный буфер хранит несколько снимков после синхронного callback. После успеха клиент сверяет снимки с результатом и записывает текст через публичный `IEcoFileSystemManagement1` в рабочий каталог. Альтернатива — `printf` из клиента — нарушала бы строгую трактовку запрета libc; вывод только в файл Eco и `cat` из shell оставляет собственные C-объекты без прямых libc-вызовов.
2. Отображаемая потеря вычисляется той же клиентской функцией на сохранённых весах после оптимизации. Это дополнительные клиентские оценки, не вызовы оптимизатора; исходные показатели производительности не меняются. Полосы `#` масштабируются относительно начальной потери каждого примера, но рядом всегда стоит числовое значение. При нулевой потере пустая полоса допустима.
3. Скрипт `run-visualization.sh` сначала запускает существующую сборку и UnitTest, затем собирает отдельный клиент теми же флагами и архивами, запускает его в каталоге Mac BuildFiles и печатает файл только при коде 0. Команда видима человеку, но не добавляет зависимость в компонент.
4. Примеры с 5 и 10 весами используют `L(w)=Σ(w_i−i)^2`, начальные координаты `w_i=2i+1` и фиксированный шаг обучения соответственно 0.08 и 0.05. Все координаты каждого снимка сверяются с независимой аналитической рекурсией `w_i(k)=i+(i+1)(1−2η)^k` до форматирования. Показаны все координаты вектора, а не его норма или только потеря; для десяти координат строка переносится после пятой.
5. Для Word-отчёта строится статический график относительной потери `L(k)/L(0)` по тем же семи значениям четырёх примеров. SVG хранит координаты и легенду, PNG получается механическим рендерингом SVG и встраивается в DOCX. Нормализация позволяет сравнить формы убывания при разных исходных масштабах 4, 21, 55 и 385; числовые таблицы сохраняют абсолютные значения.

## Risks / Trade-offs

- [Файловый сервис не может создать файл] → клиент возвращает ошибку; скрипт не печатает устаревший результат.
- [Округление скрывает численную ошибку] → клиент проверяет полный `double_t` с допуском до форматирования, а UnitTest сохраняет отдельные строгие проверки.
- [Измерения скорости спутаны с демонстрацией] → отчёт явно отделяет дополнительные оценки потерь и время терминального вывода от прежнего бенчмарка.

## Migration Plan

Старые клиенты и способы сборки не меняются. Для отката достаточно убрать отдельный клиент, скрипт и новый текст отчёта.
