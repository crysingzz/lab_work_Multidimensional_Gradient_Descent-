# Proposal

## Why

`Eco.Lab1` пока содержит только демонстрационный `IEcoLab1::MyFunction` и не решает задание № 76. Для сдачи нужен ACOM-оптимизатор произвольной функции потерь по вектору весов, проверенный консольным клиентом и сопровождаемый отчётом о точности и производительности.

## What Changes

- Добавить публичный интерфейс данных `IEcoVector` для весов `double_t` и интерфейс `IEcoArtificialIntelligence` для создания вектора и запуска многомерного градиентного спуска с пользовательским callback и контекстом.
- Реализовать центральные конечные разности, одновременное обновление координат, остановку по градиенту, ограничение итераций и определённую семантику ошибок, ссылок и владения памятью.
- Сохранить `CID_EcoLab1`, одну зарегистрированную фабрику и опубликованный ABI `IEcoLab1`; добавить новые IID и пути `QueryInterface` без изменения порядка старых методов.
- Обновить сборку и консольный UnitTest, проверить численный результат по независимому эталону и крайние случаи; подготовить Word-отчёт только с фактически полученными измерениями.

## Capabilities

### New Capabilities

- `weight-vector`: создание и безопасная работа с ACOM-вектором весов с явным владением и проверкой границ.
- `gradient-descent-optimizer`: оптимизация произвольной функции потерь, численный градиент, условия остановки и диагностика результата.

### Modified Capabilities

Нет: в `openspec/specs/` ещё нет действующих спецификаций; опубликованный `IEcoLab1` сохраняется.

## Impact

План затрагивает `Eco.Lab1/SharedFiles`, `HeaderFiles`, `SourceFiles`, `UnitTestFiles`, сборочные файлы Linux и macOS, а также новый Word-отчёт. Компонент использует только публичные интерфейсы Eco Core, InterfaceBus и MemoryManager; реализация не получает зависимостей от libc или сторонних библиотек. Внешний API расширяется новыми интерфейсами без намеренного изменения существующего ABI.
